Локаторы для Appium

Мы добавляем элементам приложения теги — постоянные идентификаторы. По тегу автотест найдёт кнопку, поле или текст, даже если надпись или вёрстка поменяются. Одна и та же строка работает на Android и на iOS.

Как искать элемент

У каждого важного элемента есть тег — короткая строка вроде access_code_key_1_button. На Android тег лежит в атрибуте resource-id, на iOS — в атрибуте name.

ГдеAndroidiOS
Java, KotlinAppiumBy.id("…")AppiumBy.accessibilityId("…")
PythonAppiumBy.IDAppiumBy.ACCESSIBILITY_ID
Page Object@AndroidFindBy(id = "…")@iOSXCUITFindBy(accessibility = "…")
XPath, запасной вариант//*[@resource-id='…']//*[@name='…']

Пример: праздничные иконки

В сборке с этой функцией после успешного обычного входа по PIN-коду или биометрии кнопка «Включить» в предложении имеет тег holiday_icon_sheet_enable_button. В профиле чекбокс имеет тег profile_holiday_icons_checkbox. Оба тега наблюдались на Android Demo через настоящий Firebase; примеры сверены по коду. Проверка этих тегов на iOS ещё ожидается.

// Android, Java / Kotlin
AppiumBy.id("holiday_icon_sheet_enable_button")
AppiumBy.id("profile_holiday_icons_checkbox")
// iOS, Java / Kotlin
AppiumBy.accessibilityId("holiday_icon_sheet_enable_button")
AppiumBy.accessibilityId("profile_holiday_icons_checkbox")

Настройка Appium

Android

Драйвер UiAutomator2 по умолчанию дописывает к id имя пакета и ищет <пакет>:id/access_code_key_1_button. У наших тегов такого префикса нет, поэтому автодополнение нужно выключить:

{
  "platformName": "Android",
  "appium:automationName": "UiAutomator2",
  "appium:disableIdLocatorAutocompletion": true
}

Теги видны и внутри диалогов, шторок и выпадающих меню. Если какой-то тег не находится по id, включите в сессии настройку mapTestTagToResourceId: true (драйвер 8.4.0 и новее) и сообщите нам про этот элемент.

iOS

Дополнительно ничего настраивать не нужно. Ищите стратегией accessibility id: она сверяет атрибут name, куда приложение кладёт тег.

Приложение строит дерево элементов само, когда его запрашивает драйвер, — VoiceOver включать не надо.

Перед прогоном на demo

Сборка demo работает с демо-базой 1С через шлюз. Убедитесь, что шлюз запущен: запустить его может любой сотрудник — разработчик, QA или аналитик.

Если в приложении бесконечная загрузка, а запросы падают по таймауту через 90 секунд, это не ошибка приложения. Кроме поломки стенда, причин обычно две: не запущен шлюз или бэкенд обновляет демо-конфигурацию — это часто бывает в течение рабочего дня. В первом случае запустите шлюз, во втором подождите.

Осторожно: настоящие действия

Как устроены имена

  • Латиница, нижний регистр, слова через подчёркивание.
  • Формат <экран>_<элемент>_<тип>, например access_code_clear_button.
  • Тип стоит в конце: _button, _input, _title, _subtitle, _text, _message, _link, _checkbox, _radio, _switch, _slider, _timer, _progress, _list, _item, _card, _image, _error, _web_view, _pdf_view, _map.
  • Одинаковые элементы получают один тег: баннеры, новости, результаты поиска, карточки. Берите их списком через findElements и выбирайте по тексту или по порядку.
  • У частей составного элемента тег продолжает тег элемента: слайдер home_loan_application_sum_slider, его заголовок home_loan_application_sum_slider_title и значение home_loan_application_sum_slider_value.
  • Элементы, которые есть на многих экранах, называются без экрана: top_bar_back_button, snackbar_message, loader. Теги dialog_title и соседние — у стандартных диалогов (запросы разрешений, диалог про уведомления). У диалога, который есть только на одном экране, теги этого экрана.
  • В тегах не бывает данных пользователя: телефона, номера карты или договора, ФИО, сумм. Тег — всегда одна и та же строка.
  • Тег не зависит от текста на экране и от темы оформления. Если тег придётся переименовать, предупредим заранее.

Часть экранов рисует не наш код, а веб-страница, сторонний SDK или система. Туда наши теги не попадут.

Системное окно

iOS: подтверждение смены иконки

Системное уведомление iOS после смены иконки не получает наших тегов. Теги holiday_icon_sheet_… относятся к шторке приложения перед главной, а не к этому окну. Системное окно и его появление на устройстве пока не проверены.

Веб-страница

Вход: телефон, код подтверждения, капча

Это страница сервиса авторизации внутри sign_in_web_view, наших тегов в ней нет. Её элементы видны в обычном дереве элементов, переключать контекст не нужно.

На Android элементы ищутся по id со страницы: например, поле телефона — phone. Контекст WEBVIEW тоже доступен, в сборках debug и demo.

На iOS id со страницы не приходят, ищите по типу и подписи: поле телефона — TextField с label «Номер телефона», кнопка — Button «Продолжить». Если нужен контекст WEBVIEW и на iOS — напишите, включим.

Капчу автотест не пройдёт. Для автотестов нужен номер или стенд без капчи — обсудим с бэкендом.

Веб-страница

Платёжная страница. На Android открывается в WebView, на iOS — в Safari поверх приложения (SFSafariViewController). На Android тег есть у контейнера: payment_web_view, bank_cards_web_view; на iOS тега нет.

  7. Дополнение: подтверждение даты рождения при входе

    В релизной ветке

    После кода со страницы входа сервер может попросить клиента подтвердить дату рождения — тогда до экрана «Задайте код» открывается ввод даты. Теги — в списке тегов, раздел «Вход: подтверждение даты рождения», с пометкой «3.0.1.0».

    Там же изменилась страница входа: верхней панели больше нет, «Назад» — красная стрелка поверх страницы. Тег стрелки прежний, top_bar_back_button, так что тесты, которые нажимают «Назад» на странице входа, менять не нужно.

    Как попасть на экран даты: дату просит сервер, если клиент давно не входил. На demo для этого дату последнего входа клиента в 1С сдвигают назад больше чем на 2 дня. У клиента 2 попытки, счётчик хранится на устройстве и сбрасывается при выходе из аккаунта. Верная дата снимает требование: чтобы снова увидеть экран, дату последнего входа нужно сдвинуть ещё раз. Неверная дата требование не снимает.

    Проверено на Android и iOS в сборке demo: ввод даты, ошибки под полем, экран расхождения с одной и без попыток, выход, стрелка на странице входа. Снекбар ошибки запроса проверен на Android. Экран «Не удалось войти» на demo не получить, его теги проверены только по коду.

    13 ноября влито в релизную ветку Release-candidate-3.0.1.0: теги и стрелка на странице входа есть в её сборках, собранных после этого. В сборках 3.0.0.0 их нет.
